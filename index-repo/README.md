# Claude Skill Drop index repository

This directory is a separate initialized local Git repository, ready to publish. It has no remote or hosted raw endpoint yet. Copy/publish its contents as the root of a new GitHub repository. The daily workflow runs on the repository's default branch.

## Run

Requires Node.js 22+. The checked-in `lib/core.mjs` contains the YAML and ZIP libraries and shared validation code, so no npm install is needed in this repository:

```text
npm run build
```

Then run `npm run verify` to check the generated schema, size, report consistency and pinned repository commits. The Action performs both commands before committing output.

In GitHub Actions this uses the workflow's built-in GITHUB_TOKEN. Locally the token is optional; leave GITHUB_TOKEN unset for anonymous public access. No credential is required for the seeded public repository. The browser extension is entirely browser-based; this scheduled index build is an offline data-production job, not an application backend.

The action is scheduled for 03:23 UTC daily (08:53 Asia/Calcutta) and supports workflow_dispatch. It commits `skills-index.json` and `skipped-skills.json`, and uploads a skip-report artifact even if indexing fails. GitHub must allow the workflow's contents:write permission and bot pushes; protected default branches may require a different publishing arrangement. The same builder and verifier have been executed successfully locally without a token; successful hosted execution is not claimed.

## Configure coverage

`config.json` supplies seed repositories, topic queries, curated README sources, page counts, repository and skill caps. Defaults scan at most 8 repositories and one page per topic. The generated report records deferred candidates, incomplete results, invalid skills, archive problems and code-search denials. This is a bounded directory, not a claim to index all GitHub skills. API responses and archives are memoized by URL within a run; one archive is fetched per processed repo/commit. API budget: 45 anonymous or 800 authenticated attempts per run. Search requests are paced at least 6.1 seconds apart. Raw/codeload requests receive no token.

For each public repository the builder resolves its actual default branch and commit, reads the recursive Git tree (with truncated-tree fallback), downloads its archive, finds all SKILL.md roots including nested roots, and checks file bytes against Git blob hashes. It never executes discovered files. YAML uses the core schema with no custom executable tags. A missing, malformed, non-string or empty name/description is reported in skipped-skills.json instead of published. Multiline strings are supported. Content is never rewritten.

## Schema

Top level: `{ "version": 1, "generatedAt": "ISO timestamp", "skills": [...] }`.

Each skill includes `repo`, `path`, `root`, `branch`, `commit`, `treeSha` (the skill folder's Git tree SHA), `skillSha` (SKILL.md blob SHA), `name`, `description`, `stars`, `updatedAt`, `fileCount`, and `previewSha256`. Nested roots also include `nestedUnder`. `updatedAt` is the repository's pushed_at timestamp, not a claim about the exact last modification of the individual skill. `fileCount` includes SKILL.md and all supporting files under the root. Parent skills retain nested skill folders, and nested skills also receive their own records.

The index is capped at 2 MiB and 5,000 records; configured limits may be lower. Omitted skills are reported. If nothing valid can be indexed, the builder writes the failure report and refuses to replace the existing index with an empty snapshot. The supplied snapshot now contains 57 real skills in 51,728 bytes, generated by the actual full local configuration: 8 repositories processed, 213 candidates discovered, 205 deferred by the cap, and 4 repositories skipped because archive responses exceeded the size limit. The report contains every processed repository's commit SHA. This is not a hosted Action run.

The seeds include anthropics/skills and sergebulaev/linkedin-skills. The latter is a skill source, not a configured hosting destination. The extension can load any public repository directly without waiting for the scheduled index or changing this configuration. Tests write their bounded fixture/snapshot outputs under artifacts/ and do not overwrite this generated production snapshot.

## Connect the extension

1. Publish this repository and run the Build skills index workflow manually once.
2. Check its run and both output files. Confirm the timestamp advances and inspect skipped-skills.json.
3. Copy the Raw URL for skills-index.json, shaped like `https://raw.githubusercontent.com/OWNER/REPO/BRANCH/skills-index.json`.
4. In the extension's Directory settings, paste the real URL and Save settings. The extension allows this host only; no GitHub Pages wildcard permission is needed.

To regenerate `lib/core.mjs` after changing shared source, run `npm.cmd run build` in the parent extension project and commit this repository's updated bundle. Preserve THIRD-PARTY-LICENSES.txt when publishing. No repository files fetched for discovery are ever imported or run.
